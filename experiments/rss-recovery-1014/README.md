# 1014 東白川村・公式簡易版の暫定監視検証

2026-11-02。検証専用。既存本番スクリプト、更新workflow、公開XMLを変更しない。

## 検証結果と範囲
- 公式HTTPSトップページのメンテナンス案内が、HTTP簡易版を直接案内している。
- 簡易版お知らせ3件：11/02産業祭、10/27駅伝募集、10/20古民家DIY。
- 既存17件へ新規2件を追加し19件。DIYはタイトル・公式掲載日が一致する既存GUIDを再使用し、リンクだけ簡易版へ変更。全17件のタイトル・GUID・日付を保持する。
- 既存17件のうちDIY以外16件は従来リンクのまま保存され、通常サイト停止中は詳細が読めない可能性がある。
- 福祉課の「戸籍の郵送請求」は掲載日不明の固定案内。PDFを検証するが、新着RSSには追加しない。
- 取得可能なPDFは5件。ファイル先頭のPDF署名とレスポンスを検証。内容の安全性や行政情報の正確性を保証する検証ではない。
- 簡易版は掲載範囲が限定され、通常の事業者・入札・支援情報の網羅性は未確認。暫定的な補完に限る。

## 安全策
- 検証workflowは専用ブランチへのpushだけで動く。contents:read、認証情報をcheckoutへ保存しない。commit/push/deployなし。結果はActions artifactのみ。
- liveごとに現在の公式HTTPS案内を確認。案内消失・構造変更・未知のHTMLページ・日付不明・URL再使用・取得/PDF失敗は停止し、既存出力を維持する。
- 掲載日はお知らせ一覧の日付だけを採用。開催日・締切・PDF名・HTTP更新日時・初回取得日時を掲載日に転用しない。RSSの日付は公式日をJSTの00:00へ統一する表現で、実際の公開時刻を意味しない。
- 本番XMLのファイル名と同名への出力、入力baselineへの上書きを禁止。全検証完了後に一時ファイルから原子的に置換。
- 暫定運用中は過去記事を切り捨てない。繰り返し生成しても同じGUIDで19件を維持する。

## 本番化する場合に必要な変更（今回は未実施）
1. 進行管理で限定的な監視範囲とHTTPの残存リスクを了承し、暫定採用を判断する。
2. 凍結fixturesではなく、その時点の公開RSS/最新保存状態をbaselineとする本番用の履歴保持処理へ接続する。以後も毎回、直前RSSと照合する。
3. 既存本番スクリプトへ明示的なtemporaryモードを追加するか、専用暫定処理を接続する。エラー時の無条件自動フォールバックは採用しない。
4. 同一の公開RSS URLを維持し、既存GUID/日付を維持。生成前後の差分を確認してから更新。Inoreader実機確認を別途行う。
5. 暫定記事URL/GUID/掲載日/タイトル/PDFハッシュを履歴へ永続保存する。同URLでの本文/PDF差替え通知は現prototypeでは未実装。

## 通常サイト復旧時の切替
自動復帰はしない。公式簡易版への案内消失を検出した時点で検証処理が停止し、レビューを要求する。
- 通常新着一覧が戻り、GitHub Actionsから取得できることを確認。
- 暫定期間全体の通常記事と暫定履歴を突合。初期3ページだけで期間が足りない場合は過去ページ/記事詳細も確認。
- DIYは既存GUID /news/detail/767 を維持し、リンクを通常URLへ戻す。
- 産業祭/駅伝の通常URLは未確認。判明時にタイトル・掲載日・本文・添付資料を照合し、明示的な対応表を作る。通常側で日付/タイトルが変わる場合は自動同一判定しない。
- 既に発行した簡易版GUIDを維持してlinkを通常URLへ変更し、同じ記事を通常URLの新規GUIDで再発行しない。
- 通常側に再掲されない暫定記事も保持し、掲載消失を削除理由にしない。未確認記事は保留リストへ残す。
- 日時/GUID/記事数の差分検査とInoreader確認後、通常モードへ明示切替。対応表と履歴を残す。

## 残留リスク
簡易版はHTTPのみで、第三者改変への耐性はHTTPSより低い。公式HTTPS側の案内確認はこの通信リスクを解消しない。
Actionsでの複数回取得成功は、将来の日次更新や掲載網羅性の保証ではない。
現prototypeは同じGUIDの本文/PDF差替えを取得できるが、RSSリーダーが再通知するかは未検証。
古い通常記事のリンク停止、新ページ追加、HTMLレイアウト変更、日付のない新着の追加には監視/再確認が必要。
